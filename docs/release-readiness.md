## 复用与恢复行为

默认严格模式保留：没有供应商证明的不变模型修订时不复用。用户明确选择的 `visible-model` 模式使用固定路线和模型目录的可见条目，接受同 ID 背后的服务器换版可能无法检测。`immutableRevision` 仍为 `null`，风险标记保留。TTL 从结果生成时计时，命中不续期；示例为 24 小时，上限 30 天，`--full` 可强制重跑。

任务定义、完整声明输入、实际请求、上游版本、执行器、策略与权限身份均参与检查。未知依赖、未知宿主安全策略或无法核实的文件权限禁用复用。DSH 会话安全身份是缓存边界。缓存包含源码及模型结果，必须位于被审查仓库之外并按源码保护。

取消行为已修复并有回归：预先取消不淘汰尚未执行任务的已有提交；中途取消只改写已经开始的新代次，未访问的独立分支保留。恢复重新核对当前输入、权限和上游版本。已经开始的新执行失败、取消或中断后，不能退回旧成功对象；下游不能绕过已重跑上游的失效。

## 历史与预算

此前已推送版本没有真实复用成功路径，先前“核心目标已经完成”的结论撤回；本次本地修订及真实验收才补齐该路径。

新四任务验收第一次完成 4 次推理后，因为 auth 报告未知依赖、summary 继承限制，未通过复用资格检查；后两阶段未执行。随后提示词 v3 澄清必要依赖与范围外局限的区别，仍要求保留真正依赖缺口，并在新仓库、新状态用 6 次推理通过完整链路。旧输出及失败记录保留，没有修改未知依赖字段来制造命中。

新增最多 10 次的授权实际用完 10 次（4 + 6）。加上原历史实验 46 次与此前单任务实测 2 次，累计 58 次真实推理；元数据 GET 另计。本记录证明本地核心验收；GitHub 发布状态以对应提交及 CI 为准，安装包以各自对应的源码、哈希与记录为准。

## 仍然适用的限制

- 模型目录不是实际生成版本的证明，供应商暗中换版的风险仍在。有效缓存也不证明完整语义依赖或结论正确。
- 未验证任意仓库的效果、普遍性能、安装后完整桌面会话或其他 DSH 版本。Windows 是实际宿主与原生权限验证目标；其他平台没有同等级验证。
- 前台运行支持取消。rc.6 的公开 jobs 接口不能保证静默完成，`background: true` 明确失败；不自动发起后续对话。
- 首版不支持跨仓库复用、自动推导完整依赖闭包、自由探索 Agent 缓存，或缓存任意脚本及写文件、发消息等副作用。
- 旧锁恢复期间再次中断可能留下无所有者恢复门，需要确认无写进程后人工隔离；本机同权限攻击者、跨文件原子快照和 Windows 断电时目录元数据持久性不在保证范围内。

## 持续集成与包边界

仓库工作流在 Windows 和 Ubuntu 上使用 Node 22.23.2 运行 `npm test` 和 `npm pack --ignore-scripts`，不提供模型凭据或发布权限。缺少已有 DSH 的宿主测试明确跳过；CI 不能把这些跳过当成宿主兼容验证。注入权限记录只用于确定性故障测试；POSIX ACL 无法证明时禁用复用。

提交与打包范围为插件源码、测试、示例、文档和经过字段筛选的证据；不包含凭据、本机原始 artifacts、完整请求或缓存对象。早期 [实现与实验记录](implementation-report.md)、[安装验证](installation-verification.md) 和 [补充审查记录](followup-audit.md) 保留原始历史，不与本次功能验收合并计算性能。
