# v0.1 发布准备检查

日期：2026-11-11（Asia/Shanghai）。范围是 README 声明的单仓库、声明输入、只读审查任务 DAG；本轮没有新增远程模型调用、凭据操作或 DSH 核心修改。

## 功能结论

已具备任务清单校验、拓扑执行、冻结输入、选择性失效、严格来源与权限检查、持久缓存、取消与恢复、CLI 及固定宿主配置的三个插件工具。未知语义依赖会使本任务及下游不具备复用资格。任务验收字段进入提示和指纹，语义正确性仍在报告中明确记为未评估。

本次定向审查确认并修复了一处取消行为：已有成功缓存时，预先取消运行会把所有任务 head 改为取消，尽管没有任务执行；中途取消也会清除尚未访问的独立分支。现在取消报告仍会持久化，只有已经开始执行代次的任务会改写 head。尚未开始执行的任务保留原提交对象；恢复时照常重新核对输入、权限和上游代次，旧汇总不能绕过已重跑上游的失效。

新增回归覆盖以下两种用户可见行为：

- 先填充缓存，再传入已取消的信号：没有新增执行，报告为取消，所有已提交代次保留；恢复全部复用。
- 修改 a 并在它执行时取消：a 的旧成功结果失效，尚未访问的 b 保留；恢复执行 a 和汇总、复用 b，汇总消费新 a 代次。

非取消的输入错误继续使对应 head 失败并阻塞下游。真正开始的新执行发生失败、取消或中断后，仍不能回退旧成功结果。

修改后执行 `node --test --test-concurrency=1 test/engine.test.js`：19/19 通过，0 失败、0 跳过，包含新增的两项取消回归，以及旧有失败、漂移、未知依赖和证据检查。

## 最小持续集成

仓库已添加 `.github/workflows/test.yml`，在 GitHub 的 Windows 和 Ubuntu runner 上分别使用 Node 22.23.2，执行 `npm test` 和 `npm pack --ignore-scripts`。官方 checkout/setup-node 操作固定到已核实的提交 SHA。项目核心与测试使用 Node 内置模块，不需要安装 npm 依赖或下载 DSH。工作流只需仓库内容读取权限，不需要模型凭据、模型端点或发布权限。

`test/dsh.test.js` 在缺少已安装 DSH 时明确跳过依赖宿主的用例，仍运行独立的 schema、休眠配置与宿主策略检查。已有本机 DSH 的验证另行执行；可通过 `DSH_TEST_RUNTIME_ROOT` 指定已有运行时。CI 的通过与跳过数量应原样保留，不能把跳过写成 DSH 兼容验证通过。

跨平台测试中的注入权限记录仅用于确定性机制与故障验证。原生权限测试仍读取实际平台信息；POSIX ACL 无法完整证明时断言禁用复用。Ubuntu 上的原生演示因此不能要求 Windows 的 4/0/2 执行数量；其保守重跑符合当前策略。

## 可接受的公开限制

- 当前官方适配器没有可验证的不可变服务端模型版本；AI 结果保存审计记录并始终重跑，不能宣称已经测得 AI 缓存节省。
- Windows 是已实测兼容目标；其他平台没有同等级宿主与权限验证。完整 POSIX ACL、后台静默 jobs、自由探索 Agent 缓存、跨仓库和任意脚本验证均不在 v0.1 范围内。
- 声明输入不证明完整依赖闭包；证据位置与结构校验不证明模型结论正确。
- 旧锁恢复过程中若进程再次中断，可能遗留无所有者的恢复门并要求人工确认后隔离。普通执行进程中断的自动恢复已经有独立回归覆盖。
- 本机同权限恶意进程、跨文件原子快照与 Windows 断电时目录元数据持久性不在当前保证范围内。

最终本机全套测试 91/91 通过，0 失败、0 跳过，包含完整的独立插件安装验证。完整测试、安装与实验结果分别以实际日志和 [实现与实验记录](implementation-report.md)、[安装验证](installation-verification.md)、[补充审查记录](followup-audit.md)、[兼容性记录](compatibility.md) 为准。本检查未发现上述取消问题以外的新功能缺口；GitHub CI 另行保留各平台实际通过和跳过数量。
