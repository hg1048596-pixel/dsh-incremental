# 补充审查与验收

日期：2026-11-11（Asia/Shanghai）。本轮目标是在既定 v0.1 范围内复查并完成可解决的验收项。未扩大到源码修改、自动工具探索、跨仓库或后台自动唤醒。

## 已修复的问题

| 范围 | 发现的问题 | 处理 |
|---|---|---|
| 缓存目录 | 状态根在仓库外，但计算后的仓库缓存目录可能落入源码目录 | 构造与初始化时同时检查状态根和最终缓存目录，预览同样受限 |
| 权限证明 | 自定义权限提供器可能同时声称已验证并提供错误或不完整字段 | 矛盾、缺失或格式错误的证据均不能启用复用 |
| 原子写入 | 写入或同步失败时可能残留临时文件 | 失败路径清理本次临时文件，保留原提交对象 |
| CLI 输出 | 仓库外的报告文件可能是源码文件的硬链接 | 执行前检查输出边界，临时文件加替换写入，避免截断被链接的源码 |
| 模型完成状态 | 完整 JSON 不足以证明响应正常结束 | 核心拒绝明确非正常的结束原因；兼容 DSH 的 `{kind:"stop"}` 结构 |
| 请求生命周期 | 关闭插件与路径检查、清单读取或私有运行时初始化存在竞态 | 再次核对取消/关闭状态，等待已接收操作结束后回收运行时 |
| 错误记录 | 供应商自定义结束标签或异常代码可能进入报告 | 仅输出固定错误码，不复制任意供应商标签或异常内容 |
| 取消实验 | 取消后可能继续创建后续执行器、修改样例，或返回成功退出码 | 停止后续阶段；取消返回非零状态；未完成配对的比较保持未知 |
| 实验控制 | 先前只按阶段开始前的样例快照声明配对一致 | 每阶段前后核对源码与清单，再核对各任务实际消费的文件摘要后评分 |
| 清理 | 一个执行器清理失败可能阻止其余执行器清理 | 尝试全部清理后统一报告错误 |
| 验证记录 | 复用报告可能把原生成阶段的检查列为本次检查 | 本次检查保留在 `validation`；历史检查独立保存在 `reusedFrom.validation` |

每个任务的报告现在包含 `inputSnapshot` 和 `upstreamVersions`，用于核对实际读取范围和上游代次。文件摘要只说明字节一致性，不保证语义依赖完整或发现正确。

## 验收证据与实验边界

本补充审查阶段统一回归 **81/81 通过，0 失败、0 跳过**，覆盖上述问题，包含原生 Windows ACL、真实进程被终止后的恢复，以及本机 DSH rc.6 的公开工具/LLM 接口。之后发布准备阶段加入了取消缓存保留、可移植证据和真实安装验证，最终本机统一回归为 **91/91 通过**，详见 [发布检查](release-readiness.md)。原生离线三轮实验和所有原始记录见 [实现与实验记录](implementation-report.md)。

临时 profile 使用本机公开的 `loadProfile`、`composeEntries` 和 `Loader` 解析实际 package.json 与 bundle patch，成功激活并卸载三个工具，网络请求为零。实际适配器与核心联动的离线测试验证了正常完成、原始结束原因持久化及模型版本未知时零复用。当时未运行包管理器；之后已完成公开 `dsh plugin add` 与现有 pnpm 的真实离线安装，详见 [安装验证](installation-verification.md)。

真实模型实验仍为此前的 **46/48 次调用**；本轮新增远程模型调用为 **0**。此前失败、增加行号后的独立复测及其原始性能数据保留，不把离线替身接口测试解释为新的真实模型检出证据。新的离线性能数据使用本轮修复后的实现；旧报告仍保留在 artifacts 中。

## 尚未解决的限制

- 官方路线没有可核实的不可变服务端模型版本，AI 结果依然仅留档、不复用。自定义名称、时间戳和环境变量不能代替版本证明。
- 普通任务进程中断可以自动恢复；若恰好在旧锁恢复过程里中断，遗留的无所有者 `writer.lock.recovery` 会保守阻止后续写入。先停用并确认相关写进程结束，再人工隔离该恢复门文件；不自动删除身份不明的锁。具体步骤和原因见 README。
- 不宣称防御能同时修改运行时代码、源码和缓存的同权限恶意进程；快照不是跨文件原子事务。
- 背景 jobs 的静默完成契约、完整 POSIX ACL、自由探索子 Agent 缓存和不可变模型身份都没有通过验证，维持已公开的限制。
- 三个合成模块与固定证据评分只验证有限机制，不构成通用代码审查能力、语义正确性或可推广节省比例的证明。

后续真正启用 AI 复用需要可验证版本的模型后端。扩大样本、测量跨模块依赖及降低权限检查开销，应在该条件具备后分别验证。
